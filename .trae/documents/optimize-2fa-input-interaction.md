# 优化 Tauri 版本 2FA 输入交互计划

## 用户反馈整理
1. **回删交互需要优化** - 当前回删逻辑不够合理
2. **进度提示不需要改** - 保持现有实现
3. **样式不需要改** - 保持现有样式
4. **增加倒计时** - 需要与真实2FA工具时间同步，而不是本地计算
5. **不做记住上次输入** - 移除该功能

---

## 当前问题分析

### 现有回删交互问题
当前 `useOtpInputs.ts` 中的回删逻辑：
- 在空输入框按 Backspace 会聚焦到上一个输入框
- 但非空输入框按 Backspace 只是删除内容，不会移动焦点

**问题**：用户期望的行为可能是：
- 按一次 Backspace 删除当前内容
- 再按一次 Backspace（此时为空）才回到上一个输入框
- 或者删除后自动回到上一个输入框

### 2FA 倒计时同步问题

**方案A：本地计算（简单但不准确）**
- 根据页面加载时间计算30秒周期
- 缺点：可能与真实TOTP生成器有时间偏差

**方案B：后端提供时间戳（推荐）**
- 后端在返回TOTP挑战时同时返回当前服务器时间戳
- 前端根据服务器时间计算倒计时
- 更准确，但需要后端配合

**方案C：标准TOTP时间窗口**
- TOTP算法使用30秒时间窗口，基于Unix时间戳
- 前端可以直接使用 `Date.now()` 计算当前处于哪个30秒窗口
- 不需要后端配合，与所有标准TOTP工具同步

**决定采用方案C**：因为TOTP是标准算法，所有验证器都使用相同的30秒时间窗口（基于Unix时间戳），前端可以直接计算。

## 优化方案

### 1. 回删交互优化

#### 当前行为
```
输入框有内容 + Backspace = 删除内容，焦点不变
输入框为空 + Backspace = 聚焦到上一个输入框
```

#### 优化后行为
```
输入框有内容 + Backspace = 删除内容，焦点不变
输入框为空 + Backspace = 聚焦到上一个输入框（保持）
新增：Delete键 = 删除当前内容，焦点移动到下一个（如果非最后一个）
```

#### 额外优化
- **左右方向键**：在输入框之间移动焦点
- **Home键**：聚焦到第一个输入框
- **End键**：聚焦到最后一个输入框

### 2. TOTP倒计时同步

#### 实现方案
- 使用标准TOTP算法的时间窗口计算
- 每个30秒窗口基于 Unix 时间戳：`Math.floor(Date.now() / 1000 / 30) * 30`
- 倒计时显示：剩余秒数 = 30 - (当前秒数 % 30)

#### UI展示
- 在输入框下方或标题旁添加倒计时指示器
- 显示格式："验证码将在 X 秒后失效"
- 最后5秒变红色提醒
- 倒计时归零时提示用户"验证码已更新，请使用新的验证码"

#### 与2FA工具同步原理
由于Google Authenticator、Microsoft Authenticator等工具都使用相同的TOTP标准：
- 时间窗口：30秒
- 起始点：Unix epoch (1970-01-01 00:00:00 UTC)
- 算法：TOTP = HOTP(K, T) 其中 T = (Current Unix time - T0) / X

因此前端计算的倒计时与所有标准TOTP工具完全同步。
