# 修复游戏进程检测弹窗交互逻辑

## 问题描述
游戏进程检测弹窗的交互逻辑有问题：
- **选择"是"**：应该杀死进程，然后继续启动游戏
- **选择"否"**：应该什么都不做（不启动游戏）
- **当前行为**：选择"否"却继续打开了游戏 & 获取新的一次性密码

## 分析

### 当前代码逻辑 (useGameLauncher.ts)
```typescript
async function checkAndKillRunningGameProcesses(gamePath: string): Promise<boolean> {
  const listResult = await safeInvoke(commands.listGameProcesses(gamePath))
  // ... 错误处理 ...
  if (listResult.data.length === 0) return true  // 没有进程，继续

  let confirmed: boolean
  try {
    await ElMessageBox.confirm(t('MsgGameAlreadyRun'), '', {
      confirmButtonText: t('Yes'),
      cancelButtonText: t('No'),
      type: 'warning',
    })
    confirmed = true  // 用户点击"是"
  } catch (cancelOrNo) {
    confirmed = false  // 用户点击"否"或关闭
  }

  if (confirmed) {
    const pids = listResult.data.map((p) => p.pid)
    await safeInvoke(commands.killGameProcesses(pids))  // 杀死进程
  }
  return true  // 无论用户选择什么，都返回 true 继续启动游戏
}
```

### 问题
函数总是返回 `true`，这意味着无论用户选择"是"还是"否"，游戏都会继续启动。

### WPF 参考行为
根据代码注释，WPF 的行为是：
- "Yes" → 杀死进程并继续启动
- "No" → 继续启动（不杀死进程）
- 但用户期望的是："No" → 取消启动

## 修复方案

### 方案：修改返回逻辑
当用户选择"否"时，返回 `false` 阻止游戏启动。

```typescript
if (confirmed) {
  // 用户选择"是"：杀死进程，继续启动
  const pids = listResult.data.map((p) => p.pid)
  await safeInvoke(commands.killGameProcesses(pids))
  return true
} else {
  // 用户选择"否"：不杀死进程，也不启动新游戏
  return false
}
```
